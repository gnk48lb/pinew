# 第 7 课：长会话（压缩、恢复、分出去）

对话越长，每一句都要把整段历史再发一遍。三件事决定这笔钱怎么花：
1. **压缩（compaction）**：历史快满时让模型写一段摘要，用摘要换掉旧历史。省的是之后每个请求的历史长度，代价是写摘要的一次请求，以及压缩那一刻前缀变了。
2. **恢复（--continue）**：关掉 pi，之后接着聊。
3. **分出去（--fork）**：从某个会话复制出一个新会话接着聊。

这一课测的是：压缩会不会让缓存断一次、摘要请求花多少、多久回本；恢复和分出去会不会让整段历史重付。
预测和判定规则已经写在路线图 11-17 那一行里（数据出来之前）。

## 你要做的（10–20 分钟，几乎全是等）

```bash
mkdir -p ~/pi && cd ~/pi && tar xzf <下载的>/pi-lesson7.tgz     # 得到 ~/pi/lesson7/
mkdir -p ~/pi-practice/l7 && cd ~/pi-practice/l7
python3 ~/pi/lesson7/session_lab.py --dry-run                   # 不调模型，先看一遍
```

看完 dry-run 之后、正式跑之前，写下两个猜测（随便一句话）：
- (a) 压缩发生后的**第 1 个请求**，会不会把整段（压缩后的）历史按新输入价重付？
- (b) 用 `--continue` 恢复一个刚关掉的会话，第 1 个请求会不会整段重付？

然后正式跑（33 个 pi 进程，约 10–15 分钟，预计 $0.02–0.12，默认花费上限 $0.40）：

```bash
python3 ~/pi/lesson7/session_lab.py 2>&1 | tee -ia ex7.log
```

跑完把 `ex7.log` 发给我，再加上：两个猜测，和“最意外的一点”。

## 它会做什么、不会做什么
- 你自己的 `~/.pi/agent` 一个字不动：脚本在 /tmp 下起私有目录，放 models.json、auth.json 的副本和实验用的 settings.json，跑完删除。
- 实验里 `cacheWarming` 关掉，会话文件放在临时目录，不会混进你平时的会话列表。
- 中途 Ctrl+C 没关系：已经跑完的运行照常汇总。
- 没测的：隔很久（十几分钟以上）之后再恢复；手动 `/compact`、`/tree`（`-p` 模式不执行斜杠命令）；摘要写得好不好；更长的会话。

## 选做（各 2 分钟，不做也行）
1. 在 pi 交互界面里聊几句，输入 `/compact`，看它给的摘要。
2. 输入 `/tree`，看会话是棵树；再试 `/fork`。
