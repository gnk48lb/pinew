# 第 5 课：扩展（动请求的各种写法，各让账单变多少）

讲义（扩展是什么、怎么加载、事件的顺序、每种写法让请求多几个 token、哪几种会让缓存失效、`budget-guard.ts` 逐行读、自测题和答案）在手册文档第 5 章。这个包里只有练习要用的东西。这一课要回答两个问题：**扩展的各种写法，各让每个请求多几个 token？** 以及 **哪几种写法会让缓存失效、失效多少钱？** 你的数据是答案的一半。

## 包里有什么

| 文件 | 干什么 |
|---|---|
| `lesson5/ext_lab.py` | 实验室，只用标准库。读你 `~/.pi/agent` 里的网关、模型、密钥和价格。`--mine 文件.ts` 可以量你自己写的扩展让每个请求多几个 token |
| `lesson5/v1-extensions/` | v1 三个扩展（`budget-guard.ts`、`preset.ts`、`safety-gate.ts`）的原样副本，和你 v1 里的逐字节相同。实验里的 S2 用它们，练习 A 从这里复制 |
| `lesson5/v1-presets.json` | v1 的 `presets.json` 副本（S2 要用） |
| `lesson5/exercises/` | 两个小练习要用的文件：`try-judge.ts`、`chain/`（6 个文件的链）、`tally-skeleton.ts` |

这些副本不会装进你的 pi：脚本只把它们复制到一个临时目录里用，跑完整个目录删掉。不需要第 1–4 课的脚本。

## 练习（一条命令，两部分合计约 8–12 分钟，多数时间在等）

**先猜两个数（30 秒）**，看输出之前写下来：（a）注册一个只有名字和一句描述的小工具（实验里 S3 那种），会让每个请求多几个 token？（b）K1（每句话都改一次系统提示的末尾）比 K0（不装扩展）每条消息多花几倍？我的十八条预测已经写进路线图文档的实验日志（11-10 那一行），在你看到数据之前就锁定了，数据到了对照着看，不改。

**正式跑**（别改次数：我写的评分规则是按这个设计定的）：

```bash
python3 ~/pi/lesson5/ext_lab.py 2>&1 | tee -ia ex5.log
```

分两部分，同一条命令。每次运行都是一个独立的 pi 进程，一个一个跑，不并行。命令里的 `-i` 别漏：它让 `tee` 在你按 Ctrl+C 时不跟着退出；不加的话，Ctrl+C 会把 `tee` 一起打断，脚本最后的汇总和“数据”就写不进 `ex5.log`（我在容器里试过两种写法）。

**第一部分（几分钟，几乎不花钱）**：9 种配置各跑 4 次，每次只问一句“Reply with exactly the single word: OK”，读发出去的请求里总共有多少输入 token。9 种配置里，S0 是不装扩展的对照，其余每个臂比它多出来的 token 就是那种写法的价钱：

| 臂 | 扩展做了什么 |
|---|---|
| `S0` | 不装扩展（对照） |
| `S1` | 观察型：订阅 13 种事件，什么都不返回 |
| `S2` | 你的 v1 三个扩展一起装 |
| `S3` | 注册一个工具 `today`（名字、一句描述、没有参数） |
| `S4` | S3 再加 `promptSnippet` 和 `promptGuidelines` |
| `S5` | 在 `before_agent_start` 里给系统提示加一段 `team_rules` |
| `S6` | 强制替换 `systemPrompt`（在原文后面加一句） |
| `S7` | 返回一条 `message`（追加一条用户消息） |
| `S8` | `context` 钩子：在最后一条用户消息末尾加一块文字 |

**如果这一部分有运行写着“核对没过”，或者一个数据都没拿到，第二部分不会开始**：把屏幕上的内容贴给我就行。

**第二部分**：5 种配置各跑 5 次，每次连问三句。第 1 句带一段约 16,000 字符（3,000 多个 token）的固定参考文本，第 2、3 句是一个词的回答。量的是**第 2、3 句里有多少输入 token 没有命中缓存**：

| 臂 | 扩展做了什么 | 第一个变了的字节在哪 |
|---|---|---|
| `K0` | 不装扩展（对照） | 没有变 |
| `K1` | 每句改一次系统提示末尾（`sections`） | 系统提示的末尾，整段历史的前面 |
| `K2` | 追加式：每句追加一条固定的消息 | 没有变（只在末尾追加） |
| `K3` | `context` 钩子：在最后一条用户消息末尾加一块文字 | 上一条用户消息的末尾 |
| `K4` | `context` 钩子：在第一条用户消息最前面加一块 `[ctx N]` | 历史的开头，系统提示的后面 |

每次运行时脚本都会读 pi 实际发出去的系统提示和扩展留下的标记，核对它正是这个臂该有的；不对的运行记失败，不进统计。屏幕上每完成一次出一行；跑完会打印几张表，最后是每次运行一行的原始数据。想中途看进度，别关窗口；想停，按 Ctrl+C，已有的结果会照样汇总。

**交作业（1 分钟）**：把 `~/pi-practice/l5/ex5.log` 发给我，加上你的两个猜测，再用一两句话说哪一点最意外。别删最后那段“数据”，我算分用的就是它。

## 费用和安全

- **花费**：用你 `models.json` 里的价格算。预计 0.02–0.06 美元；花费到 `--max-cost`（默认 0.30 美元）脚本自己停下，并在汇总里说明。练习 A、B 各只有几个请求，通常不到 1 美分。
- **不动你的配置**：跑的时候把你的 `models.json`、`auth.json` 复制一份到 `/tmp/ext-lab-xxxx`（权限 600，只有你能读），再放进实验用的扩展，跑完整个目录删掉。你真正的 `~/.pi/agent` 一个字不动，你的 AGENTS.md、你装的扩展也不会被读到（每个 pi 都带着 `--no-session --no-extensions -ns -np -nc`；实验用的扩展是脚本自己用 `-e` 显式装上的）。
- **只给模型 `read` 工具**（S3、S4 再加 `today`，它只返回日期）：模型不能改文件、不能跑命令。
- **没连过你的网关**：这个脚本我在我这边用一个假网关（带模拟的前缀缓存）加真的 pi 1.5.0 测过（扩展真的装上了、请求里多出来的东西对得上、核对失败的处理、失败重试、超时、花费上限、Ctrl+C 清理、不动你的配置、解压出来的包本身、用我的评分脚本打分），但没连过你的真网关。缓存到底怎么算，是这个实验要量的东西，第一次对着真网关跑的是你。

## 选项（一般不用）

`--only cost` 只做第一部分；`--only position` 只做第二部分；`--arms S3,K1` 只测几个臂；`--model provider/模型id` 换模型；`--max-cost 美元` 改花费上限；`--dry-run` 不调模型；`--mine 文件.ts` 量你自己的扩展（它注册了工具的话，再加 `--mine-tools 工具名`）。正式跑请不要加其中改设计的选项（`--only`、`--arms`、`--model`、`--reps1`、`--reps2`）：脚本头一行的“设计指纹”只覆盖脚本里写死的设计（扩展的写法、请求、判定标准、各臂的次数），不覆盖你在命令行上加的选项，我算分时按默认设计读。
