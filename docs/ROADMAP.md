# ROADMAP — 从 v1.0.0 到“日常主力”

写于 2026-11-22/23，上一个 session 的最后一份文档。**这是推荐顺序，不是合同**：用户说“这里别扭”（记进 `FRICTION.md`）永远优先于本表；同类摩擦出现第二次就插队。技术上的取舍你自己定，只把“只有他才知道的事”（日常做什么任务、口味、能接受的风险）拿来问他，一次一个问题、二选一。

## 0. 先看这几条

1. **这个模型下，钱不是瓶颈。** 一个 4.4k token 的前缀整段全价重算 = 约 $0.00066，命中 = $0.000066（[MM] 算术，FACTS A3）；中途切一次档位约 $0.0006（5k 历史）、$0.0054（4 万历史）。所以**不要为了省 $0.00001 牺牲功能**。缓存护城河要守，理由是：①长会话里 10× 的价差；②延迟；③前缀可预测、可量；④别让没用的指令/工具稀释模型的注意力。**真正的瓶颈是：用着顺不顺手、改坏了能不能撤、结果可不可信。**
2. **v1 在评测里“没测出伤害，也没测出收益”**（[DS, pi 1.3.0]，FACTS §J）。评测台已经饱和（开发题 144/144），它只能回答“有没有变差”，回答不了“有没有变好”。所以**质量改进靠用户每天用出来的反馈，不靠比赛**；评测台只在里程碑当回归闸（见 v2.0）。
3. **一个版本 = 用户拿到手能感觉到的一件事。** 每版都能单独装、单独退回。写不出“用户会感觉到什么”的改动，先别做。
4. **别重写官方已有的。** pi 1.5.0 的 `examples/extensions/` 有 79 个示例（`plan-mode/`、`todo.ts`、`git-checkpoint.ts`、`handoff.ts`、`custom-compaction.ts`、`custom-footer.ts`、`jev-router.ts`、`notify.ts`、`tools.ts`、`subagent/`…），文档和示例就在 npm 包里（`$RT/node_modules/@earendil-works/pi-coding-agent/{docs,examples/extensions}`）。读它们的源码、改成适合我们的样子，比从零写稳；但**读过源码才用**，并量前缀。

## 1. 版本号怎么对应

- 用户说的“v1.1、v2、v3…” ≈ 这里的里程碑；中间的 1.x 是为了让每一步都能单独发出去。semver：新功能加 minor，不兼容的改动（会改 `~/.pi/agent` 里的东西、改默认行为）加 major。
- 旧文档（`archive/`）里的 “v1 / v1.1 / v1.2” 指同一套实测过的配置（安全带的补丁版本号），**等于本仓库的 `v1.0.0`**。旧路线图里写的 “v1.1 候选”（预设 `tools` 的 `+名字/-名字`）在这里归到 1.2.0。
- 每个 tag 都要有 `CHANGELOG.md` 条目（pi 在包更新时会显示它）和 `docs/STATE.md` 的更新。

## 2. 发布计划

### v1.0.0 ✔ 基线（本仓库的第一个提交）

实测过的 v1 字节级原样（哈希 `docs/baseline/v1-SHA256SUMS.txt`）+ pi 包外壳（`package.json`）。在沙箱的 pi 1.5.0 上验证过：包能加载（`/preset`、5 个提示模板、2 个技能），安全带拦得住 `rm -rf old`。**还没装进用户的 WSL；而且装的话会撞上双装崩溃（HANDOFF §5.1）。**

### v1.1.0 机制：能装、能退、能自检　〔P0，第一件事〕

用户感觉到的：**一条命令装好/升级/退回；装完行为和以前一样。**

范围：
- `tools/pinew.py`：`status`（只读：装了什么、和基线差在哪）· `install [--dry-run]`（迁移 + 装包 + 放置配置）· `undo`。**在 `tools/legacy/install_v1.py` 的骨架上改**（先检查再动手、`--dry-run`、先写 MANIFEST、原子写入、读回核对、只撤自己装的、不碰 `models.json`/`auth.json`/`sessions/`）。
- 迁移规则（HANDOFF §5.1 的双装崩溃是死穴）：对 v1 的 12 个文件逐个比对基线哈希——一致 → 删掉复制品；被改过 → 搬进备份并提示；用户自己加的文件 → 不碰；**只按文件名精确动手，绝不整目录删**（`~/.pi/agent/` 同时是托管安装的根）。然后 `pi install <本地路径>`，再放置 `AGENTS.md`、合并 `settings.json`。
- **缺 `presets.json` 时 `--preset` 静默无效**（HANDOFF §5.2）：优先让 `preset.ts` 把包内 `config/presets.json` 当最底层默认读（单一来源，`git pull` 即生效）；做不到再让安装器放置。这是对基线文件 `preset.ts` 的**有意改动**，写进 CHANGELOG。
- `AGENTS.md`/`settings.json` 不是包资源，只能由安装器放置。放置方式（拷贝+哈希追踪 / 符号链接）你定；原则：用户改过就不覆盖，只提示。
- `tools/check.py`（沙箱里一条命令，无网络、不花钱、≤2 分钟）：①包加载无重复无报错（`dev/rpc_commands.py`）②安全带仍拦 `rm -rf old`（print 模式）③`--preset explore/deep` 生效（工具表 + 指令都变）④三轮会话前缀逐轮严格追加（mock 的请求转储）⑤发给模型的 system+tools 与基线快照字节一致（有意改动要 `--update-golden` 并写 CHANGELOG）⑥基线文件哈希 ⑦密钥扫描 ⑧安装器场景（假 HOME：全新 / 复制式 v1 / 被改过的 v1 / 带用户自己的文件 / 被强杀的断点），`undo` 后与安装前逐字节一致。
- `tools/smoke.*`（用户在 WSL 跑，两三条命令，<$0.002）：迁移前后各跑一次固定的 `pi -p … --mode json --no-session`，对比首个请求的 `input+cacheRead+cacheWrite`（应相等，容差 ±70 即已知异常 B12）。

验收：
- 沙箱：`python3 tools/check.py` 全绿。
- WSL：`pinew.py install --dry-run` 打印的计划与 `collect-state.py` 的输出一致；正式安装后 `pi list` 里 pinew 只出现一次，`dev/rpc_commands.py` 列出的命令和装之前相同；`pi --preset explore` 生效；`undo` 能回到装之前；烟测前后首请求 token 数相等。
- 前缀：`+0 tokens/request`（只是搬家，不该变）。
- 打 tag `v1.1.0`，STATE/CHANGELOG 更新。

用户要做的：贴 `collect-state` 输出 → 看 `--dry-run` 计划说“好” → 贴安装输出 → 跑烟测贴结果。（共 4 次，每次一条命令。）

### v1.2.0 开局多档位　〔P1，用户点名的第一块短板〕

用户感觉到的：**开一个会话时，一句话选到合适的“档”**，而不是在 explore 和 deep 之间凑合。

设计要点：
- **在开局选，不在中途切。** 实测中途换 thinking/工具白名单/预设指令各断一次缓存（FACTS B5），所以 `pi --preset 名字` 是主路径；`/preset` 保留，但文档里写明“一次性断缓存，约 $0.0006（5k 历史）~ $0.0054（4 万历史）”。（官方示例 `jev-router.ts` 也是“一个会话只切一次、认一次缓存未命中”。**有意的、一次性的切换可以；自动的、反复的不行。**）
- 先问用户**一个问题**：日常主要做什么（改自己的项目 / 写脚本运维 / 读别人的代码 / 混合）；再看 `pi --list-models` 和 `collect-state` 里的 models.json，才有依据决定档位要不要带 `model`（**默认不带**，没有明确的更便宜/更强的备选就不换模型）。
- 建议起点（可改）：`quick`（low，全套四工具，指令“最小改动、先做再说”）· `explore`（v1，只读）· `plan`（只读 + 要求输出计划，不动手）· `deep`（v1，high，全工具 + 验证）· `review`（只读 + 看 diff）· 有便宜模型时加 `cheap`（机械批量活）。每个档位一行用途说明，进 `/preset` 的列表。
- 启动方式：别让用户记一串参数。可选：安装器可选地在 `~/.local/bin/` 放几个小启动脚本（如 `pq`/`pe`/`pp`/`pd`/`pr`，`undo` 会删）或让用户一次性粘贴几行 alias——**问他一次，二选一**。
- **修 preset 的 tools 与 MCP 的坑**（FACTS G3）：读源码所得 [src]——`preset.ts` 用 `pi.setActiveTools(validTools)` 整体替换工具表，所以 MCP 入口（`codemode`/`tool_search`/`mcp__*`）被一并关掉；而 CLI 的 `--tools` 文档说“MCP 工具默认保留，除非条目以 `mcp__` 开头”，且支持纯 `+名字/-名字` 的相对写法。办法：在 `preset.ts` 里保留当前已启用的 MCP 入口，或让预设的 `tools` 支持 `+名字/-名字`。
- 每个档位的首请求前缀（token）要**在用户的真网关上量一次**（`tools/measure-tiers.py`，每档一条 `pi --preset X -p … --mode json`，总共 <$0.005），结果写进 FACTS 并标 `[MM, pi 1.5.0]`。mock 的 token 数是近似的，别当真。

验收：
- `check.py` 新增：每个档位启动后，请求里的工具表和指令与设计一致；带一个 MCP 服务器（`labs/lesson6/mcp/mini_mcp.js`）时，开局 `--preset explore` 和中途 `/preset explore` 之后 MCP 入口都还在。
- 用户的真机：每档能起；测量表贴回。
- 前缀：`quick` 档 ≤ v1 默认 + 150 token（纪律，不是铁律；超了要在 CHANGELOG 说明换来了什么）。
- 用户用一周：**不再手改配置去凑档位**；`FRICTION.md` 里档位相关的条目关掉。

### v1.3.0 撤得回（+ 逐轮花费/命中）　〔P2〕

用户感觉到的：**agent 改坏了，一句 `/undo` 回到这一轮之前。**

- 官方 `git-checkpoint.ts`（53 行）已读：每轮 `turn_start` 做一次 `git stash create`，只在 `/fork` 时提示还原，且 `agent_settled` 就清空 → **不够当 undo**，`git stash create` 也**不含未跟踪文件**。要做的是：检查点要跨轮保留（建议放 `refs/pinew/…` 而不是 stash 列表）、包含未跟踪文件（临时 index 技巧）、`/undo` 先给“撤销前”再做一个检查点（撤销本身可撤销）、非 git 目录优雅降级成一行提示、**绝不对用户未提交的改动做无检查点的 `reset --hard`/`clean`**。
- 逐轮花费/缓存命中：pi 的 footer **已经**显示累计 token、花费、上下文占用（docs/usage.md）；`showCacheMissNotices` 已开。**只在用户说“想看每轮”时才补**（`custom-footer.ts` 是现成模板），不要先做。
- 纯扩展代码 0 前缀；`/undo` 是命令不是工具。

验收：在临时 git 仓库里用 mock 脚本让“模型”改几个文件 + 新建一个未跟踪文件 → `/undo` 全部还原（含未跟踪）→ 再 `/undo` 的撤销也能撤；非 git 目录不报错；0 前缀。用户真机：一次真实的“改坏再撤”。

### v1.4.0 不迷路：计划、待办、验证闭环　〔P2〕

用户感觉到的：**大改动前先给计划，改完自动跑测试、失败了自己接着修。**

- **计划模式**：先读官方 `plan-mode/`（`index.ts`+`utils.ts`，`/plan` 开关只读、从 `Plan:` 小节抽编号步骤、`[DONE:n]` 追踪进度）。注意**命名冲突**：v1 的 `prompts/plan.md` 也叫 `/plan`——采用扩展就改名或删模板。切换会改工具表（断一次缓存，FACTS B5），可接受。
- **待办**：`todo.ts` 注册一个工具 → **每个请求 +42 ~ +95 token**（FACTS C7）；只在需要的档位启用（工具白名单管所有工具，F3）。
- **验证闭环**（质量上收益最大、风险也最大）：模型改完文件、说“完成”后，如果项目配了验证命令（例如 `.pi/verify.json`：`{"cmd":"npm test"}`，`/init` 可帮着生成），扩展跑一遍，失败就**追加一条消息**把输出交回去（追加安全，FACTS B3），最多 2 轮，超了就停下并汇报。默认关，用 `/verify` 或档位开启。**风险**：死循环、跑到危险命令（走安全带）、输出太长（截断到 2,000 字符以内）。
- AGENTS.md 候选一行：“规格与测试矛盾时按规格实现、测试不动、如实报告；不要为了变绿去改测试配置或跳过测试”（FACTS J4，[DS] n=3，每行 +41 token）。**只有用户碰到过这种情形才加。**

验收：mock 场景“改坏 → 验证失败 → 追加消息 → 修好 → 通过”走通且 ≤2 轮；达到上限时停下；前缀逐轮追加的检查仍绿；每个新增工具/规则在 CHANGELOG 声明 `prefix: +N tokens/request`。

### v1.5.0 子代理产品化　〔P2，可选：只有摩擦指向“反复读大文件/大日志”才做〕

第 8 课的结论是**不要默认开**（FACTS I10）：固定开销 $0.00127、追问 ≥6.3 句才回本、回传超过 ~12k 字符就失效。产品化只是把这些限制做进去：回传上限（工具硬截断并声明“已截断”）、`usage` 回传（让 footer 的花费包含子代理，F4）、辅助模型可选（有便宜的才用）、只在需要的档位启用（+42~95 token）。起点：`labs/lesson8/lab8_ext.ts`，对照官方 `subagent/`。

验收（沿用第 8 课的口径，[MM] n≥4/臂）：追问成本 ≤0.25×“自己读”，回本 ≤7 句，回传 ≤上限（10/10）；“回复里没有的细节”主会话老实说不知道（不编造）。

1. v1.1–v1.4 都已发布并装在用户的 WSL 上（1.5 可选）。
2. 用户用 pinew 当主力至少 2 周；`FRICTION.md` 里没有未处理的“高”条目。

## 3. 每个版本的完成定义（DoD）

1. `tools/check.py` 全绿（v1.1 之前用 HANDOFF §4 第 4 条的手工清单）。
2. `CHANGELOG.md` 有条目，含 `prefix: +N tokens/request`（没有就写 0，并说明怎么量的、带标签）；`package.json` 版本号同步。
3. 迁移/卸载：新增会落到 `~/.pi/agent/` 的东西，必须有 `--dry-run`、`undo`，并在假 HOME 里测过。
4. 会进模型请求的改动（工具、技能、规则、MCP）：前缀成本已量；有风险的（新工具、改请求的钩子、动安全带/预算护栏）让用户真机冒烟一次（一条命令，先说明花多少钱、多久、会不会改他的机器）。
5. `docs/STATE.md` 更新；新实测数字写进 `FACTS.md`（带 `[模型, pi 版本, n, 真网关/mock]`）；tag；推送。
6. 用户听得懂的一句话：这一版他会感觉到什么。

## 4. 实验纪律（轻量版）

只在需要**真网关数字**时才做实验，且：
- 做之前写三行：预期是什么；这个 n 能分辨多大的差别；对照臂是什么（FACTS L7：背景会随机整段重付，长请求约 20%，所以每格 ≥5 次、必须有对照）。
- 成本控制：每个实验默认 <$0.05；要超就先告诉用户并等他点头；告诉他要花多久、会不会改机器。
- 数字写进 FACTS 之前，用原始日志复算一遍；复算不上的不写。
